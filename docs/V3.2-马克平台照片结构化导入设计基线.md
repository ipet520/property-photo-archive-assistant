# V3.2 设计基线 v1.1

## 马克开放平台照片结构化导入版

状态：已封版，可进入分阶段开发。

## 1. 总体架构

```text
马克 API 查询
→ 用户勾选照片
→ 主进程事务式下载
→ 保存来源清单与结构化数据
→ 生成工作台导入包
→ 追加并去重进入现有工作台
→ 人工确认
→ 复用现有预览、归档和台账流程
```

核心原则：新增照片来源，不新建平行归档系统。

马克照片默认使用平台结构化字段。本地照片继续使用 OCR；马克照片仅在用户主动选择时使用 OCR 或 AI 作为异常补充。

## 2. 安全与存储边界

- 组织 KEY 只在 Electron 主进程使用。
- 使用 Electron `safeStorage` 加密后保存到 `userData`。
- 前端只能读取是否已配置、组织 ID、更新时间和连接状态。
- KEY 不得进入设置导出、备份、日志、错误详情、前端草稿或 IPC 返回值。
- 签名计算和 API 请求统一在主进程执行。
- 便携版移动到其他 Windows 用户或设备后，应要求重新输入 KEY。

正式下载目录：

```text
文档\物业工作照片归档助手\marki-import\
  <orgId>\
    <teamId>\
      <拍摄日期>\
        <momentId>.jpg
```

`.runtime` 只用于开发测试，不保存正式业务来源照片。

## 3. 来源标识与去重

```text
sourceType = marki_api
sourceKey = marki_api:<orgId>:<momentId>
```

同一 `sourceKey` 不重复下载、不重复创建照片对象、不重复进入工作台。

现有照片对象只增加：

```text
sourceType
sourceKey
sourceMetadataRef
capturedAt
```

完整接口明细由主进程保存，前端照片对象继续使用现有的 `originalPath`、`originalName` 和 `previewUrl`。

## 4. 字段映射

| 软件字段 | 马克来源 | 规则 |
| --- | --- | --- |
| 日期 | 日期 → 时间 → postTime | 水印拍摄时间优先，上传时间只兜底 |
| 项目 | 小区名称 | 匹配现有项目或别名，未匹配时要求确认 |
| 归档分类 | markName | 匹配现有分类或映射规则，未匹配时保留候选 |
| 工作内容 | 工作内容 → 标题 | 过滤占位值 |
| 位置/区域 | 地点 → 有效经纬度 | 零坐标保持为空，由归档层按现有规则显示“现场” |
| 拍照人员 | 上传人 | 查询和来源追踪使用，同时保留 uid |
| 备注 | 工作备注 | 无有效内容时不生成空字段 |
| 来源追踪 | id、teamId、防伪码 | 保存到主进程来源明细 |

机动车水印的工作内容采用：

```text
违停类型 + 车牌号
```

## 5. 字段清洗

以下值视为空：

```text
请输入……
请选择……
未填写
暂无
空字符串
纯空格
模板默认占位值
```

处理顺序：

```text
解析 content
→ 规范字段名
→ 清洗字段值
→ 过滤占位内容
→ 执行映射
→ 生成候选归档建议
```

## 6. 事务式下载

```text
建立 downloading 来源记录
→ 下载到 <momentId>.jpg.part
→ 校验 HTTP 状态
→ 校验文件非空
→ 校验 JPEG 文件头
→ 校验图片宽高
→ 原子改名为 <momentId>.jpg
→ 写入来源清单
→ 标记 imported
→ 生成工作台导入包
```

失败时记录明确原因并标记 `download_failed`，允许重试。未完成最终改名和来源清单写入前，不得进入工作台。

## 7. 工作台导入包

```javascript
{
  batchId,
  photos,
  recognitionResultsByPhoto,
  watermarkRecordsByPhoto,
  archiveSuggestionsByPhoto
}
```

马克结构化识别结果：

```text
source: marki_api
providerType: structured_data
status: recognized
```

识别成功不等于已整理、已确认或已归档，仍须进入现有人工确认链路。

## 8. 开发范围

V3.2 包含：

- 安全凭证、请求签名和连接测试。
- 团队列表、成员列表、照片分页查询。
- 筛选、勾选、事务式下载、失败重试。
- `momentId` 去重、来源清单和状态管理。
- `content` 清洗、字段映射和工作台导入包。
- 追加并去重进入现有工作台。
- Excel 来源摘要和主进程来源明细。

V3.2 不包含：

- 视频导入。
- 定时同步、Webhook 和多组织切换。
- 自动归档、自动创建项目或分类。
- 修改或删除马克平台数据。
- 全组织历史照片自动下载。
- AI 场景校验。

## 9. 实施顺序

1. API 基础设施：安全凭证、签名、连接测试、团队和成员查询。
2. 下载与来源管理：事务式下载、来源清单、状态、去重和重试。
3. 数据转换：字段清洗、匹配、映射和工作台导入包。
4. 页面衔接：查询筛选、照片选择、进度和追加进入工作台。
5. 追溯与回归：Excel 摘要、来源明细、归档关联和原有流程回归。

## 10. 阶段验收与下一阶段边界

V3.2 第一阶段“马克平台 API 基础能力”已经人工验证通过并封版：

```text
组织 KEY 安全加密保存
连接测试正常
团队列表正常
成员分页正常
KEY 不回显、不进日志
团队不自动选中
成员电话不进入前端
重启后配置可继续使用
```

第二阶段范围冻结为：

```text
来源清单
→ sourceKey 去重
→ downloading 状态
→ .part 事务下载
→ 文件头、大小和宽高校验
→ 原子改名
→ imported / download_failed 状态
→ 下载失败重试
```

第二阶段不得接入工作台，不做字段映射，不修改现有归档流程。

## 11. 官方接口附录

### 获取组织的团队列表

- 请求方式：GET 或 POST。
- 请求地址：`https://open-api.markiapp.com/marki/org/team`。
- 业务参数：无。
- 分页：无。
- 响应列表：`data.teamOrgList`。
- 团队字段：`teamId`、`teamName`、`createUID`、`manageUIDs`、`createTime`、`parentTeam`、`OrganizeId`。

### 获取团队的成员列表

- 请求方式：GET 或 POST。
- 请求地址：`https://open-api.markiapp.com/marki/team/mem`。
- 参数：`teamId`、`next`。
- 分页：将响应的 `data.next` 原样传给下一次请求，直到 `data.hasMore` 为 `false`。
- 第一页统计：`regTotal`、`unRegTotal`、`total`。
- 响应列表：`data.memberList`。
- 成员字段：`uid`、`nickname`、`phone`、`joinTime`、`memberType`。
- 软件只向前端返回筛选需要的 `uid`、`nickname`、`joinTime` 和 `memberType`，不返回电话号码。

公共请求头、签名规则和响应状态码沿用马克开放平台 `1.API 使用` 文档。
